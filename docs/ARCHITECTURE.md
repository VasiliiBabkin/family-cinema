# Архитектура Android-first 0.3.0

Главный контракт: [ARCHITECTURE_ANDROID_FIRST_V03.md](ARCHITECTURE_ANDROID_FIRST_V03.md). FastAPI остаётся отдельным вспомогательным проектом, приложение не обращается к нему. Сервер, БД PostgreSQL, Jellyfin или аккаунт для основного сценария не нужны.

## Модули

| Модуль | Функция |
| --- | --- |
| app | Compose phone/tablet/TV, Activity lifecycle, ViewModel, Room repository и Android Keystore |
| domain | Неизменяемая версия и точное одобрение, будущие типизированные интерфейсы |
| parental | Существующий солёный PIN/PBKDF2, блокировка попыток, совместимое хранилище 0.2 |
| player | Один retained ExoPlayer на ViewModel, video-only PlayerView, Media3 progressive/HLS/DASH |
| sources | Kotlin Stremio protocol, нормализация поиска, HTTPS/DNS policy, чистые правила автоодобрения |
| backend | Опциональный Python experiment; API/SQLite/search/policy tests, не зависимость APK |

MainActivity содержит оболочку и ActivityResult системного выбора файла. CinemaViewModel владеет навигацией/родительской сессией/единственным ExoPlayer. LibraryController владеет UI-снимком библиотеки и отменяемыми foreground-действиями. Экраны разделены: CatalogPage, WorkPage, SourcesPage, PolicyPage, LibraryComponents; основная оболочка/плеер 0.2 сохранены.

Назначение `AnimatedContent` передаётся в `LibraryUi` явным параметром: исходящий экран не читает изменившийся ключ текущего экрана. Это исключает одновременное создание двух форм назначения при переходе. На TV секретные URL вводятся системным `EditText` через официальный `AndroidView`: маскирование, ограничение длины, запрет персонализированного обучения IME, стандартное завершение ввода и освобождение фокуса. На телефоне/планшете остаётся Material Compose. TV-композиция не получает мобильное изменение отступов от IME; нормальный ввод и повторные переходы проверены отдельным инструментальным тестом.

## Данные и обновление

Room cinema.db содержит Work, Episode, Version, Source, WorkSource, Profile, Decision, Progress, Favorite, Audit. Фильм/сериал и конкретный воспроизводимый файл разделены. WorkSource связывает одно произведение с несколькими провайдерами; IMDb ID объединяется только при совпадении type/стабильного внешнего ID. Совпадение похожего названия не сливает разные фильмы. Неизвестные provider IDs остаются в namespace источника.

Экспортированы схемы 2/3/4/5. Миграции: 1→2 журнал, 2→3 связи источников, 3→4 снимок contentHash решения, 4→5 expectedSha256 версии. Эти версии Room — промежуточные схемы реализации; опубликованный 0.2 не имел Room. Отдельная атомарная и идемпотентная инициализация переносит его demo approval/position из SharedPreferences, оставляет PIN нетронутым и создаёт policy с auto OFF. Destructive migration fallback не применяется.

Основной профиль child имеет отдельные ключи решений/истории/избранного. UI нескольких профилей пока отсутствует. Родительская роль живёт только в памяти, не сериализуется и не восстанавливается после процесса. Существующий PIN-хеш не пересчитывается в новый формат при обновлении.

## Родительский gate

Каждое изменяющее действие LibraryController проверяет текущую родительскую сессию. Lock увеличивает generation, отменяет запросы и очищает родительские списки сразу. Асинхронный refresh читает данные в локальный снимок; применяет его лишь после последнего suspend при неизменной generation/роли. Старый ответ не может вернуть родительский каталог ребёнку.

Детская выборка содержит только версии с актуальным exact fingerprint, проверенным содержимым, разрешением и подходящим известным возрастом. То же проверяется перед запуском, избранным и выбором карточки. Поиск ребёнка фильтрует только разрешённую локальную выборку; источники/URI/ключи и взрослый журнал не выводятся. Внешние VIEW intents не используются.

Системный picker может остановить Activity, поэтому возвращённый URI не является авторизацией. Подготовленный родителем запрос хранится в памяти максимум 5 минут; после реального фона для импорта нужен PIN. После смерти процесса запрос пропадает. SAF-файл копируется в private storage, постоянный доступ к исходному URI для воспроизведения не нужен.

## Версии, кеш и автоодобрение

Ребёнку выдаётся immutable private copy с SHA-256. Fingerprint включает work/version/episode/source/locator/content identity; URI шифруется, для fingerprint используется расшифрованное значение. Файл перепроверяется перед воспроизведением. Изменившееся содержимое не наследует разрешение. История привязана к версии; родительский online preview не продвигает детский прогресс.

Автоодобрение — транзакция Room: ON, явно доверенный источник, rights eligibility, verified bytes (для удалённого автоодобрения также обязательный ожидаемый SHA-256 от источника, совпавший с копией), известный возраст ≤ limit, отсутствие manual deny. ContentHash tombstone запрещает автоматически разрешать те же байты под другой ссылкой. Ручной allow — отдельное подтверждённое решение. OFF не удаляет ранее выданные разрешения. Политика и результаты сохраняются в Audit.

Медиа-копии: default 2 ГБ, parent presets 1/2/4 ГБ, резерв физического места 64 МБ, progress/cancel. Удаление неразрешённых копий подтверждаемое; разрешённые не вытесняются. Обложка загружается явным родительским действием только для источника с подтверждёнными правами, максимум 2 МБ/8192 px. Private poster files ≤32 МБ, Coil disk cache 16 МБ и memory cache 24 МБ. ImageLoader общий, не создаётся на каждую карточку.

Отдельные stream-only addons поддерживаются без каталога: между источниками передаются только стабильные IMDb ID или явно объявленные idPrefixes. Совпадение названий не используется для запроса чужого stream resolver.

## Сеть

OkHttp 4.12 использует единственный проверяющий DNS-resolver; те адреса, которые проверены, передаются сокету. Запрещены IP literals, private/loopback/link-local/служебные адреса, опасные IPv6 transition ranges и redirects. TLS/hostname verification стандартные, без trust-all. System HTTP proxy не используется, поскольку он может самостоятельно разрешить имя и обойти pinned DNS; произвольный LAN/прокси — отдельная будущая интеграция.

JSON ограничен 2 МБ и таймаутами; медиа-копии — дисковым бюджетом и 30-минутным пределом вызова, чтение 30 s. Манифесты HLS/DASH ограничены 8 МБ, включая неизвестный Content-Length. Remote Media3 DataSource поддерживает только HTTPS и не открывает вложенные file/content/asset URI. Local data source используется только для проверенных локальных входов. Остановка/lock отменяют calls и освобождают idle connections.

Source endpoints и video locators шифруются AES-GCM ключом Android Keystore. Remote poster/background locators тоже сохраняются шифрованными; локальные пути остаются private. Токены, credentials и полные приватные URI не записываются в Audit или приложение logger. Backups отключены. Отдельного SDK авторизации для произвольных headers/DRM нет.

## Сохранённый плеер 0.2

ExoPlayer создаётся на main с applicationContext, переживает Activity recreation в ViewModel. CinemaVideoView отвязывает поверхность/SurfaceHolder callback; paused surface восстанавливает кадр точным seek. Контролы едины для touch/D-pad/OK/Back и скрываются через 3.5 s; таймер в viewModelScope. UI читает снимок Media3, не native getters при Compose recomposition.

Телефон запрашивает sensor landscape, планшет сохраняет ориентацию, TV fullscreen. WindowPresentation сохраняет исходные requestedOrientation и system bars через recreation. Back сначала скрывает контролы, затем освобождает плеер и возвращает экран. Фон ставит ребёнку паузу, взрослый preview закрывает вместе с сеансом.

Сетевая интеграция, физические устройства, кодеки и производительность подтверждаются только конкретными результатами QA. Torrent engine в APK нет; отдельный JNI feasibility probe не равен P2P-воспроизведению.
