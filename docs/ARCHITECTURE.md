# Архитектура 0.2.0 — Player & Native UX

## Границы модулей

| Модуль | Ответственность |
| --- | --- |
| `app` | Activity, состояние сеанса, Compose-экраны, проверка локального файла и маршрутизация ввода |
| `domain` | Произведение, точная версия, fingerprint одобрения, контракт каталога |
| `parental` | Закрытое локальное хранилище PIN-хеша, одобрений, позиции и блокировки попыток |
| `player` | Создание ExoPlayer на main с applicationContext, аудиофокус, обработка отключения наушников, шаг перемотки |
| `sources` | Будущие типизированные SourceAdapter / TorznabAdapter / TorrentEngine, без реализаций |
| `backend` | FastAPI health и типизированный пустой каталог; PostgreSQL и синхронизации ещё нет |

`MainActivity` задаёт русскую конфигурацию, получает ViewModel, устанавливает Compose и передаёт события foreground/background. В нём нет экранов, проверки PIN, бизнес-логики одобрения или создания плеера.

`CinemaViewModel` сохраняется при пересоздании Activity. Он владеет типизированным `Screen`, временной родительской сессией и единственным ExoPlayer. В UI вынесены `CinemaApp`, `PinScreen`, `CatalogScreens`, отдельные `TvScreens`, `PlayerScreen`, `PlayerControls`, `DesignSystem`, собственный векторный `NightArtwork`. Русские интерфейсные строки находятся в `res/values/strings.xml`; текст каталога в domain остаётся содержимым, а не интерфейсными подписями.

## Сеанс воспроизведения

1. Открытие возможно только родителю либо для точно одобренной версии.
2. Файл читается в Dispatchers.IO и проверяется SHA-256. До успешной проверки ExoPlayer не создаётся.
3. ViewModel создаёт плеер на главном потоке через `viewModelScope`, используя applicationContext. Повторный вызов при открытом экране игнорируется. UI не создаёт плеер в `remember` или во время пересчёта Compose.
4. `PlayerScreen` привязывает PlayerView к существующему объекту. FIT сохраняет пропорции. Стандартный controller PlayerView отключён; единственный слой PlayerControls на Compose содержит настоящие play/pause, ±10 секунд и Slider. Ложных кнопок субтитров/следующего эпизода/настроек нет. Аудиофокус и noisy events обрабатывает Media3.
5. Позиция сохраняется раз в секунду при STARTED, при уходе в фон и перед выходом. После конца ролика позиция сбрасывается.
6. Выход или очистка ViewModel отменяют открытие файла и вызывают release. CinemaVideoView отвязывается, SurfaceHolder callback и оконный callback снимаются. Для нового paused surface выполняется точный seek к текущей позиции, чтобы восстановить кадр без нового ExoPlayer.

| Событие | Поведение |
| --- | --- |
| Поворот / изменение размера | В этом Activity обработаны configChanges; адаптивная Compose-композиция обновляется |
| Пересоздание Activity | Тот же ViewModel и ExoPlayer; новый PlayerView привязывается к нему |
| Реальный уход в фон | Пауза и сохранение позиции; родительская сессия закрывается |
| Фон из родительского предпросмотра | Плеер освобождается, экран возвращается к детям; неутверждённое видео не остаётся доступным |
| Возврат ребёнка из фона | Тот же сеанс на паузе; автоматического запуска со звуком нет |
| Завершение процесса | Родительская авторизация не восстанавливается; одобрения и последняя сохранённая позиция остаются локально |

На телефоне запрашивается sensor-landscape; планшет сохраняет свою ориентацию, TV остаётся полноэкранным. Исходная ориентация, видимость панелей и оконное поведение сохраняются один раз в примитивном `WindowPresentation` внутри ViewModel и восстанавливаются при реальном выходе. При конфигурационном пересоздании старое окно не сбрасывает ориентацию текущего сеанса.

Контролы Compose располагаются поверх видео и скрываются автоматически через 3.5 секунды воспроизведения без взаимодействия. Выход/название показываются в том же слое. ControlsVisible и таймер взаимодействия едины для касаний, пульта и Back. Таймер принадлежит ViewModel и не зависит от UI frame clock; scrubbing удерживает панель открытой. Back сначала скрывает видимые контролы, следующий Back выходит. `PlayerKeys` временно подключён через публичный `Window.Callback`: OK и стрелки показывают скрытый слой, затем D-pad управляет обычным Compose-фокусом. Видеоповерхность не перехватывает фокус кнопок. Медиа-клавиши обращаются к тем же действиям плеера. Исходный callback обязательно восстанавливается; Activity/View в ViewModel не сохраняются.

## Нативные оболочки и доступность

Телефон: верхняя Android-панель, один смысловой центр экрана, вертикальные детали и компактная цифровая клавиатура. Планшет от 600 dp: NavigationRail и двухколоночные детали/PIN. TV определяется реальным UI_MODE_TYPE_TELEVISION: отдельная композиция с большой обложкой, короткими действиями, более крупной типографикой, явной рамкой фокуса и начальной фокусировкой.

Токены цвета, типографики, радиусов и фокуса находятся в DesignSystem. Переходы учитывают системное отключение анимаций. Иллюстрация статическая и не создаёт тяжёлых фоновых эффектов. Кнопки имеют размер от 48 dp; действиям-иконкам заданы русские accessibility labels. PIN озвучивается числом введённых цифр, а не самими цифрами. Фактический статус TalkBack и физических пультов указан только в QA.md.

## Сохранность и ограничения

Схема `family_private` совместима с 0.1.0: обновление не сбрасывает PIN, одобрения и позиции. Родительская роль только в памяти, отсутствует в SavedState/диске. PBKDF2-HMAC-SHA256, случайная соль, 120000 итераций, константное сравнение; пять ошибок дают минутную блокировку. Резервное копирование и перенос приватных данных отключены. Debug APK не защищает от авторизованного ADB, root и очистки данных.

Нет разрешения INTERNET, внешнего поиска, браузера, P2P и удалённых URI в детском интерфейсе. Добавление этих функций, нескольких профилей и временных лимитов выходит за рамки 0.2.0. Источники и будущий движок сохранены как интерфейсы. Совместимость ABI, кодеков и физических устройств нельзя выводить из упаковки универсального APK.

Состояние Media3 (playing, duration, position) копируется listener-ом и main-ticker-ом в Compose state. Пересчёт Composable не обращается к native getters ExoPlayer: это предотвращает доступ к плееру с потока фонового пересчёта.
