# Family Cinema — этап 2: каталог и поиск

## Принцип
Каталог произведений, конкретные видеофайлы и источники поиска — **разные сущности**. Нельзя показывать ребёнку найденный источник до родительского одобрения конкретной версии. Нельзя приравнивать совпадение названия к одобрению файла.

## Модель данных
- Work: стабильный внутренний ID, русский заголовок, оригинальный заголовок, альтернативные названия, тип (фильм/сериал/мультфильм), год, описание, возрастная рекомендация, постер с лицензией/атрибуцией, языки, provenance метаданных.
- Season/Episode: ID, номера, названия и связь с Work.
- MediaCandidate: ID, adapter ID, source reference, формат, заявленные дорожки, размер, availability, discovery timestamp. До верификации не является доверенной версией.
- MediaVersion: неизменяемая идентичность содержимого, fingerprint, проверяемый digest при наличии и конкретный episode ID. Изменение URI/хеша/эпизода аннулирует прежнее одобрение.
- Approval: parent/profile, точный fingerprint версии, дата, revoke status. Отзыв должен немедленно исключать воспроизведение в детском режиме.
- PlaybackProgress: profile, media version, position, updated timestamp; синхронизация с конфликтами по явно определённым правилам.
- SourceAdapterConfig: тип, endpoint, credential reference, health/status. Секреты никогда не отправляются клиенту.

## Контуры безопасности
1. Публичные метаданные/обложки не дают право на воспроизведение.
2. Поиск внешних источников доступен только родителю после аутентификации.
3. Детский API возвращает **только** разрешённые версии и разрешённые метаданные.
4. Backend не принимает профиль/роль из произвольного заголовка как доказательство полномочий. Требуются настоящие токены, expiry, привязка устройства и серверная проверка.
5. Запретить SSRF в source gateway: allowlist доменов, проверка DNS/IP после редиректов, блокировка loopback/private/link-local/metadata, ограничение размера/времени ответа.
6. Данные поставщиков и обложки считать недоверенными. Не передавать API-ключи, tracker credentials или полный magnet в журналы.
7. Нет результатов — честное пустое состояние, а не вымышленные фильмы.

## Поиск
- Русский запрос — основной. Unicode NFKC, casefold, ё/е, пробелы и пунктуация; дополнительные алиасы и кириллица -> латиница.
- В backend/app/search_normalization.py уже добавлены чистые функции ключей и консервативного prefix match. Это **не** полноценный движок опечаток, ранжирования или онлайн-поиска.
- Следующий уровень: точное совпадение > начало заголовка > совпадение токенов > ограниченная нечёткая близость; год и эпизод учитываются отдельно. Не смешивать разные произведения по одному похожему названию.
- Отображать происхождение и лицензию метаданных. TMDB и аналогичные каталоги — метаданные, не источник прав на видео.
- Разделять «Найти фильм» (метаданные) и «Найти доступную версию» (источники, только родитель).

## API — план, не реализовано
- GET /v1/catalog?profile=... — каталог, разрешённый для данного авторизованного профиля
- GET /v1/works/{id} — карточка
- GET /v1/search?q=... — поиск метаданных с пагинацией
- GET /v1/parent/candidates?work_id=... — поиск источников (parent only)
- POST /v1/parent/approvals — одобрение точной версии
- DELETE /v1/parent/approvals/{id} — отзыв
- GET/PATCH /v1/progress — позиции просмотра
- GET /v1/health — диагностический статус компонентов без секретов

Не включать перечисленные endpoints, пока нет хранения, реальной авторизации и тестов. Текущий /catalog остаётся честно пустым.

## Этапы реализации
A. PostgreSQL migrations + repositories + проверенная аутентификация и профили; тесты прав доступа.
B. Импорт легальных метаданных, кеш, нормализация и поиск, состояния offline/empty/error.
C. Клиентские экраны каталога, поиск, детали, прогресс; child mode только approved.
D. Адаптеры источников и торрент-воспроизведение — отдельная последующая работа после безопасности и базового каталога.

## Приёмка
Тесты разделения ролей, прямого доступа по ID, изменения версии, отзыва одобрения, пустых результатов, некорректных запросов, pagination, SSRF, rate limiting и конкурентных обновлений. Скриншоты телефона/планшета/TV; реальный backend и реальное воспроизведение только разрешённого тестового контента.
